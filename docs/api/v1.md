# Viby v1 API

This is the normative contract for the current Viby-native SDK. Viby v1 means the product API generation, even while the npm package is released under `0.x` during early development.

## Ownership boundary

The host application owns:

- authentication and authorization;
- model-provider credentials and the selected AI SDK provider;
- its user, organization, subscription, and product UI;
- Postgres provisioning and `DATABASE_URL`;
- any future preview or deployment adapter.

Viby owns:

- tenant- and user-scoped chat history;
- durable generation attempts and usage;
- resolved skill snapshots;
- immutable, parent-linked source versions;
- framework-native source ZIPs;
- migrations for the dedicated `viby` schema.

There is no Viby API key, managed Viby database, preview URL, deployment URL, or provider connection in v1.

## Installation and environment

```bash
npm install @viby/sdk ai
npx viby db migrate
```

```dotenv
DATABASE_URL=postgresql://postgres:postgres@localhost:5432/viby
```

The selected AI SDK provider reads its own environment variables. Viby records the provider and model IDs plus token usage, but never stores the provider credential.

## Client

```ts
import { createViby, skillRead } from "@viby/sdk";
import { openai } from "@ai-sdk/openai";

const viby = createViby({
  framework: "farm",
  model: openai("gpt-5.6-sol"),
  skills: {
    core: [skillRead("./skills/product")],
    design: ["owner/repository/design-skill"],
    frontend: ["owner/repository/frontend-skill"],
    security: [],
  },
});
```

### `VibyConfig`

```ts
interface VibyConfig<Framework extends string> {
  framework: Framework;
  model: LanguageModel;
  skills?: Record<string, readonly SkillReference[] | undefined>;
}

type SkillReference =
  | `${string}/${string}/${string}`
  | { source: "file"; path: string };
```

`framework` is one type-safe string, not an array. Built-in suggestions include `farm`, `tanstack-start`, and `next`, while custom framework strings remain legal. Framework-specific behavior is supplied through skills and the model prompt instead of a hard-coded `defineFramework` registry.

`model` is any AI SDK `LanguageModel`, so the application can choose a direct provider, a gateway, or its own compatible model implementation.

`skills` are categorized. Built-in categories are `core`, `product`, `design`, `frontend`, `backend`, `data`, `ai`, `testing`, `security`, `accessibility`, `performance`, and `delivery`; custom categories are allowed. `skillRead(path)` points at a local `SKILL.md` file or its containing directory. A string uses the stable skills.sh-compatible `owner/repository/slug` form.

### Methods

```ts
interface Viby<Framework extends string> {
  readonly framework: Framework;
  forUser(scope: UserScope): ScopedViby<Framework>;
  close(): Promise<void>;
}

interface UserScope {
  tenantId: string;
  userId: string;
}
```

Call `close` during process shutdown or at the end of a short-lived script.

## Tenant and user scope

```ts
const userViby = viby.forUser({
  tenantId: organization.id,
  userId: session.user.id,
});
```

Both values are required, non-empty application identifiers. Every repository query constrains both values. The SDK does not infer identity from request globals and does not query the host application's auth tables.

## Chats

```ts
interface ChatCollection<Framework extends string> {
  create(input?: { title?: string }): Promise<Chat<Framework>>;
  get(id: string): Promise<Chat<Framework>>;
  list(options?: { limit?: number }): Promise<Array<Chat<Framework>>>;
}

interface Chat<Framework extends string> {
  readonly id: string;
  readonly title: string;
  readonly framework: Framework;
  readonly createdAt: Date;
  readonly updatedAt: Date;

  generate(input: { prompt: string }): Promise<Version<Framework>>;
  latestVersion(): Promise<Version<Framework> | null>;
  getVersion(id: string): Promise<Version<Framework>>;
  listVersions(): Promise<Array<Version<Framework>>>;
  listMessages(): Promise<MessageData[]>;
}
```

`create` only creates a durable chat. `generate` adds the user message and a pending generation in one transaction before contacting the model. The promise resolves only after a successful immutable version and assistant message have been committed.

`list` defaults to 20 and accepts 1–100. Records are ordered by most recently updated. `get` and `getVersion` throw `NotFoundError` when the resource is missing or outside the current scope.

## Versions and iteration

```ts
interface Version<Framework extends string> {
  readonly id: string;
  readonly chatId: string;
  readonly generationId: string;
  readonly parentVersionId: string | null;
  readonly number: number;
  readonly framework: Framework;
  readonly title: string;
  readonly summary: string;
  readonly createdAt: Date;

  iterate(input: { prompt: string }): Promise<Version<Framework>>;
  files(): Promise<VersionFile[]>;
  generation(): Promise<GenerationData>;
  download(): Promise<DownloadArtifact>;
}
```

`iterate` generates from that exact version, even when it is not the latest. The result is a new complete snapshot whose `parentVersionId` is the selected version. Historical rows and files are immutable.

`files` returns paths sorted lexicographically. Each file contains `path`, `content`, `mediaType`, byte `size`, and a SHA-256 `checksum`.

## Generations and messages

Every attempt has one of `pending`, `succeeded`, or `failed`. Viby persists:

- provider and model identifiers;
- input, output, and total tokens when the provider returns them;
- timestamps and error text;
- the user and assistant messages;
- the exact skills and content hashes used by the attempt;
- the base version from which generation started.

A failed request stores its failure and does not create an assistant message or partial version. The thrown `GenerationError` contains `generationId`, so the host product can correlate logs and support requests without exposing a secret.

Generated projects use Structured Outputs. Every file includes a required `mediaType` field that may be `null`; a null value is replaced by Viby MIME inference before persistence.

## Downloads

```ts
const artifact = await version.download();

artifact.filename;    // e.g. analytics-dashboard.zip
artifact.contentType; // application/zip
artifact.bytes;       // Uint8Array
artifact.toResponse();// standard Web Response
```

The ZIP is built from the selected persisted version. It is the raw framework-native source tree and excludes secrets, lockfiles, dependency folders, build output, and provider-specific deployment configuration.

## Persistence model

| Table | Purpose | Written when |
| --- | --- | --- |
| `viby.chats` | scoped conversation and selected framework | chat creation and successful generation title update |
| `viby.messages` | user/assistant conversation | attempt creation and successful completion |
| `viby.generations` | attempt state, model IDs, usage, errors, base version | before and after every model call |
| `viby.versions` | immutable source snapshot metadata and parent lineage | successful completion |
| `viby.version_files` | complete files for one immutable version | successful completion |
| `viby.skill_snapshots` | content-addressed resolved skill files | first use of each exact skill revision |
| `viby.generation_skills` | ordered category/activation links | attempt creation |
| `viby.schema_migrations` | migration ledger | explicit CLI migration |

Migrations are explicit, transactional, and protected by a Postgres advisory lock. Application requests never run migrations implicitly.

## Error contract

All SDK errors extend `VibyError`:

- `ConfigurationError`: invalid config, prompt, identifier, or generated source shape;
- `DatabaseNotReadyError`: `viby` migrations have not been applied;
- `NotFoundError`: missing or out-of-scope resource;
- `SkillResolutionError`: local or remote skill could not be safely resolved;
- `GenerationError`: the durable model attempt failed.

## Not in v1

The following names are intentionally not stubbed. Applications should not have to discover at runtime that a declared method is unavailable:

- async/streaming/cancel/resume generation;
- source import, attachments, mutable chat metadata, favorites, forks, or deletion;
- in-place version editing, file deletion, restore, or tarball output;
- preview execution, screenshots, hosted URLs, deployments, provider credentials, or GitHub export.

See [`v0-core.md`](./v0-core.md) for the audited parity roadmap and persistence rules.
